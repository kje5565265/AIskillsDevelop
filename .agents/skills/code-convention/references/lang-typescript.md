# TypeScript 언어 층 (L2)

TypeScript 코드를 쓸 때의 언어 차원 룰. `strict: true` 를 전제한다.

---

## §1. 네이밍

| 대상 | 규칙 | 예 |
|---|---|---|
| 타입 (type / interface / class / enum) | PascalCase | `ScoreModel` |
| 변수 · 함수 · 메서드 · 프로퍼티 | camelCase | `remainingTime` |
| 모듈 스코프 상수 (진짜 불변) | UPPER_SNAKE | `MAX_SPEED` |
| 파일 | 기본 export가 클래스·컴포넌트면 PascalCase, 그 외 camelCase | `GameModel.ts` / `difficulty.ts` |
| 타입 파라미터 | `T` 접두 또는 의미 있는 이름 | `TPayload` |

- 인터페이스에 `I` 접두를 붙이지 않는다 (C#과 다르다). TypeScript 관례가 아니다.
- **불리언은 상태를 읽히게** — `is` / `has` / `can` / `should` 접두.
- **약어는 두 글자까지만 대문자 유지** — `id`, `ui` 는 소문자, 세 글자 이상은 `Json`, `Http`.

## §2. 타입 엄격성

- **`any` 금지.** 타입을 모르면 `unknown` 을 쓰고 좁혀서 쓴다. `any` 는 그 지점부터 타입 검사를 통째로 끈다.
- **타입 단언(`as`) 을 최소화**한다. 단언은 "컴파일러보다 내가 더 안다"는 주장이라, 틀리면 런타임에 터진다. 대신 타입 가드(`is` 반환 함수)로 좁힌다.
- **non-null 단언(`!`) 금지.** 실제로 null 일 수 있으면 분기하고, 절대 아니라면 타입 설계를 고친다.
- `@ts-ignore` / `@ts-expect-error` 는 **사유 주석 없이 쓰지 않는다.**
- 외부 입력(네트워크 응답 / 로컬 스토리지 / URL 파라미터)은 **타입이 아니라 검증으로** 받는다. 선언한 타입은 런타임에 아무것도 보장하지 않는다.

## §3. 타입 설계

- **`interface` 는 확장 가능한 객체 형태**, **`type` 은 유니온·교차·매핑·함수 시그니처**에 쓴다. 둘 다 되는 경우 프로젝트 안에서 일관되게 하나로 간다.
- **`enum` 대신 유니온 리터럴 + `as const`** 를 우선한다. `enum` 은 런타임 객체를 만들고 tree-shaking 을 방해한다.
  ```ts
  const GameState = { Ready: 'ready', Playing: 'playing', Over: 'over' } as const
  type GameState = (typeof GameState)[keyof typeof GameState]
  ```
- **불변을 기본값으로** — `readonly` 프로퍼티, `readonly T[]`, `as const`.
- **판별 유니온(discriminated union)** 으로 상태를 표현하면 불가능한 상태를 타입 단계에서 막을 수 있다. 여러 개의 `boolean` 플래그 조합보다 낫다.
- 옵셔널(`?`)을 남발하지 않는다. "있을 수도 없을 수도"가 많아지면 호출부마다 분기가 늘고 진짜 계약이 흐려진다.

## §4. null / undefined

- **`null` 과 `undefined` 를 섞어 쓰지 않는다.** 프로젝트 안에서 "값 없음"의 표현을 하나로 정한다(보통 `undefined`).
- `?.` / `??` / `??=` 를 적극 사용한다 — TypeScript 에서는 안전하다.
- `||` 로 기본값을 주지 않는다. `0` / `''` / `false` 가 falsy 라 의도치 않게 대체된다. `??` 를 쓴다.

## §5. 모듈

- **named export 를 기본**으로 한다. default export 는 이름이 임포트 지점마다 달라져 검색·리팩터가 어렵다.
- **배럴 파일(`index.ts` 재export)을 남용하지 않는다.** 순환 참조와 번들 비대의 주원인이다.
- **순환 의존이 생기면 설계 신호다.** 우회하지 말고 공통부를 아래 계층으로 뽑는다 (`SKILL.md` Part A 원칙 2).
- 경로 별칭(`@/`)을 쓰면 프로젝트 전체에서 일관되게 쓴다. 상대 경로와 섞지 않는다.

## §6. 비동기

- **`async` 함수의 반환을 그냥 버리지 않는다.** 대기하지 않을 거면 `void promise` 로 의도를 명시하고 `.catch()` 를 단다. 처리되지 않은 rejection 은 조용히 사라진다.
- 순차 실행이 필요 없으면 `Promise.all` 로 병렬화한다. 루프 안 `await` 는 직렬화된다.
- **취소를 받는다.** 오래 도는 작업은 `AbortSignal` 을 받아 전달한다.

## §7. 에러

- **`Error` 서브클래스를 던진다.** 문자열이나 객체 리터럴을 던지면 스택 트레이스가 없다.
- `catch (e)` 의 `e` 는 `unknown` 이다. `instanceof Error` 로 좁힌 뒤 쓴다.
- **삼키지 않는다.** 빈 `catch {}` 금지. 최소한 로그를 남기고, 복구 불가면 다시 던진다.
- 정상 흐름에서 예상되는 실패는 예외가 아니라 **반환값**(결과 유니온 / `undefined`)으로 표현한다.

## §8. 성능 — 매 프레임 경로

게임 루프처럼 매 프레임 도는 코드에서는 할당이 곧 GC 스파이크다.

- **루프 안에서 객체·배열·클로저를 새로 만들지 않는다.** `map` / `filter` / 스프레드 / 구조 분해 결과가 전부 새 할당이다.
- 벡터·좌표 같은 값은 **재사용 객체에 덮어쓴다**(in-place). 매번 `{ x, y }` 를 만들지 않는다.
- 문자열 조립을 매 프레임 하지 않는다. 디버그 표시는 값이 바뀔 때만 갱신한다.
- 콜백을 인라인 화살표 함수로 매번 넘기면 매번 새 함수다. 핫패스에서는 미리 바인딩해 둔다.

## §9. 주석

### 무엇을 쓰나

- **「왜」를 쓴다. 「무엇」은 코드가 말한다.** 자명하지 않은 **제약 · 전제 · 함정**을 남긴다 — 호출 순서 의존, 외부 API 의 이상 동작, 성능상 일부러 비직관적으로 짠 부분.
- **주석이 필요할 만큼 복잡하면 먼저 이름과 구조를 고칠 수 있는지 본다** (`SKILL.md` Part A 원칙 2).

### 형식

- **언어(한국어/영어)는 L4(`project-rules.md`)에서 정한다.** 정해져 있지 않으면 **그 파일의 기존 주석 언어를 따른다.** 한 파일 안에서 섞지 않는다.
- JSDoc(`/** */`)은 **외부에서 쓰는 공개 API** 에만 단다. 타입은 TypeScript 가 이미 표현하므로 `@param {string}` 처럼 **타입을 중복 기술하지 않는다** — 설명만 쓴다.
- **`// TODO:` 에는 제거 조건이나 시점을 함께 적는다.** 조건 없는 TODO는 영구 잔존한다.
- **임시 디버그 출력의 마커 형식과 제거 절차는 `SKILL.md` Part D 가 원본이다.** 여기서 다시 정의하지 않는다 — 언어 무관 규칙이라 층마다 두면 사본이 갈린다.

### 금지

- **주석 처리된 코드를 남기지 않는다.** 이력은 버전 관리가 갖는다.
- `@ts-ignore` / `@ts-expect-error` 를 **사유 주석 없이** 쓰지 않는다 (§2).
- **주석 어투 다듬기 금지** (`SKILL.md` Part B §2) / **주석을 근거로 판단하지 않는다** (Part B §1).

## §10. 기타

- **`switch` 로 타입 분기를 하기 전에 `SKILL.md` Part A 원칙 1(다형성)** 을 먼저 검토한다. 판별 유니온의 `switch` 는 예외 — 그건 다형성의 함수형 표현이다.
- 유니온을 `switch` 로 처리할 때는 **exhaustive 체크**를 넣는다(`default` 에서 `never` 할당). 케이스가 늘면 컴파일이 깨져 알려준다.
- **매직 넘버 금지.** 이름 있는 상수로 뽑거나 설정 파일로 뺀다.
- `console.log` 를 출시 코드에 남기지 않는다. 로거를 경유한다.
