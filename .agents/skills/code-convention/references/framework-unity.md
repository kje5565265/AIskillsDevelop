# Unity 층 (L3)

Unity에서 C#을 쓸 때만 성립하는 룰. **`lang-csharp.md`(L2)를 override 하는 항목이 있다** — 특히 §1.

---

## §1. `UnityEngine.Object` null 처리 — L2 override

Unity는 `UnityEngine.Object` 의 `==` 를 오버로드해, **네이티브 객체가 파괴된 래퍼를 null로 취급**한다. 그런데 `?.` / `??` / `??=` 는 이 오버로드를 타지 않고 **참조가 살아있으면 non-null로 판정**한다.

```csharp
// ✗ 파괴된 GameObject 인데도 Foo() 가 호출되어 MissingReferenceException
_target?.Foo();
var t = _cached ?? FindTarget();   // 파괴된 _cached 가 그대로 반환됨

// ○
if (_target != null) { _target.Foo(); }
var t = _cached != null ? _cached : FindTarget();
```

- `UnityEngine.Object` 파생(`GameObject`, `Component`, `MonoBehaviour`, `ScriptableObject`, 에셋 타입)에는 **`?.` / `??` / `??=` 금지**.
- 순수 C# 클래스에는 L2대로 자유롭게 쓴다.
- `bool` 로 캐스팅하는 관용 표현(`if (obj)`)도 오버로드를 타므로 안전하지만, **명시적 `!= null`** 을 권장한다.

## §2. MonoBehaviour 컴포넌트 추출 판정

Part A 원칙 2(책임 경계)를 Unity에서 집행하는 구체 기준.

**추출한다 (Strong)**

- 서로 다른 두 종류 이상의 대상(플레이어/적, 여러 프리팹)이 같은 기능을 필요로 한다
- 한 컴포넌트에 도메인이 2개 이상 쌓였다 (예: 캐릭터 로직 + 이펙트 + UI)
- 같은 기능이 다른 오브젝트에서 재사용될 가능성이 명백하다
- 기능에 **자체 생명주기**(타이머 / 상태 머신 / 코루틴)가 있다

**보류한다 (Weak)**

- 한 오브젝트에서만 쓰이고, 코드 50줄 미만이고, 외부에 노출하지 않는다
- 프로토타입 단계이고 감각 검증 전이다

**금지**

- 컴포넌트로 분리해놓고 **부모 오브젝트의 구체 타입을 다시 참조**하기 (Part A 원칙 1 위반과 결합)
- **형제 컴포넌트를 직접 찾기** — `GetComponent<Other>()` 로 옆 컴포넌트를 붙잡지 않는다. 부모(소유자)를 경유하거나 이벤트/인터페이스로 통신한다
- 분리했는데 발신자가 여전히 수신자의 상태를 직접 조작 — 신호만 보내고 정책은 수신자가 결정한다 (Part A 4축 분해)

### 재사용 공용 레이어 — Unity 구체 카테고리

Part A 원칙 2 자가검증 5항목의 적용 대상:

애니메이션 이벤트 수신부 / 두 종류 이상 프리팹에 붙는 공용 MonoBehaviour / 인터페이스 구현부 / 베이스 클래스 / 싱글턴·매니저·서비스 / 확장 메서드·정적 헬퍼 / 공용 ScriptableObject 정의 / 오브젝트 풀

## §3. 데이터·아트 vs 로직 분업

| | 담당 |
|---|---|
| **C#** | 게임 로직, 상태 머신, 계산, 데이터 모델 |
| **인스펙터 / ScriptableObject** | 튜닝 수치, 에셋 참조, 프리셋 |
| **프리팹** | 비주얼 컴포지션, 컴포넌트 배치 |

- **같은 로직을 코드와 에셋 양쪽에 분산하지 않는다.** 한쪽이 단일 진실원이어야 한다.
- **권장 형태**: C#이 `[SerializeField]` 로 훅을 제공하고, 인스펙터·ScriptableObject는 값만 채운다.
- **수치를 코드에 하드코딩하지 않는다.** 밸런스는 데이터로 주입한다.
- 아트 교체가 예정된 프로젝트에서는 **로직이 특정 에셋 이름·구조에 의존하지 않게** 한다.

## §4. 생명주기 대칭

`OnEnable` / `OnDisable` 은 오브젝트가 **비활성화·재활성화될 때마다** 호출된다. `Awake` / `OnDestroy` 는 한 번뿐이다.

| 등록 | 해제 |
|---|---|
| `OnEnable` 에서 이벤트 구독 | `OnDisable` 에서 해제 |
| `Awake` 에서 등록한 전역 상태 | `OnDestroy` 에서 해제 |

- **구독 위치와 해제 위치의 짝을 맞춘다.** `Awake` 에서 구독하고 `OnDisable` 에서 해제하면, 재활성화 때 구독이 사라진 상태가 된다.
- `Start` 에서 다른 오브젝트를 참조한다. `Awake` 에서는 아직 초기화 순서가 보장되지 않는다.
- **스크립트 실행 순서에 의존하지 않는다.** 순서가 필요하면 명시적 초기화 메서드를 호출한다.

## §5. 코루틴

- **코루틴의 수명은 그것을 시작한 MonoBehaviour 의 수명**이다. 오브젝트가 비활성화되면 코루틴은 **중단되고 재개되지 않는다.**
- 그래서 코루틴 안에서 잡은 상태·플래그는 **누수된다.** 켜는 코루틴이 있으면 `OnDisable` 에 정리 경로가 있어야 한다 (Part B §4 생명주기 검증).
- 오브젝트 수명과 무관해야 하는 대기는 코루틴이 아니라 **매니저 쪽 타이머**로 옮긴다.
- 시작한 코루틴 핸들을 보관해 `StopCoroutine` 으로 확실히 멈춘다. 문자열 오버로드는 쓰지 않는다.

## §6. 매 프레임 경로

- **`Update` 안에서 할당하지 않는다** — LINQ, 문자열 결합, 람다 캡처, 새 컬렉션. 모바일·WebGL에서 GC 스파이크는 그대로 프레임 드랍이다.
- **`GetComponent` / `Find` / `Camera.main` 을 `Update` 에서 호출하지 않는다.** `Awake` / `Start` 에서 캐시한다.
- 빈 `Update()` 를 남기지 않는다 — 호출 비용이 그대로 든다.
- 매 프레임 필요 없는 로직은 **주기 실행**(N프레임마다 / 코루틴 / 이벤트 구동)으로 내린다.
- 디버그 로그를 무조건 조립하지 않는다. 문자열 조립 자체가 비용이다.

### 시간

- **경과 시간은 `Time.deltaTime` 으로 계산한다.** 프레임 수를 세거나 고정값을 더하면 기기·리프레시레이트마다 게임 속도가 달라진다.
- 일시정지·슬로우모션은 **`Time.timeScale`** 로 만든다. 그 영향을 받으면 **안 되는** 것(UI 애니메이션 / 연출 타이머 / 네트워크 타임아웃)은 **`Time.unscaledDeltaTime`** 을 쓴다.
- `timeScale = 0` 일 때 `WaitForSeconds` 는 진행하지 않는다. 일시정지 중에도 돌아야 하면 `WaitForSecondsRealtime`.

### 문자열 조회 캐시

- `Animator` 파라미터는 문자열 대신 **`Animator.StringToHash` 로 캐시한 해시**를 쓴다.
- 셰이더 프로퍼티도 마찬가지로 **`Shader.PropertyToID`** 로 캐시한다.

## §7. 오브젝트 풀

- **풀에 반환할 때 상태를 전부 리셋**한다. 남은 타이머·구독·플래그·트랜스폼이 다음 대여자에게 새어간다.
- 반환 후에는 그 참조를 들고 있지 않는다.
- 리셋 책임은 **풀이 아니라 대상 컴포넌트**가 갖는다 (`IPoolable.OnReturn` 같은 계약).

## §8. 빌드 · 심볼 · IL2CPP

### 8.1 조건부 컴파일

- 에디터 전용 코드는 `#if UNITY_EDITOR` 로 감싼다. 감싸지 않으면 빌드가 깨진다.
- 디버그·치트 코드는 `#if DEVELOPMENT_BUILD || UNITY_EDITOR` 로 감싸 **출시 빌드에서 심볼이 남지 않게** 한다.
- 로그 헬퍼는 `[Conditional("UNITY_EDITOR")]` 로 호출부까지 제거되게 한다 — `#if` 로 본문만 비우면 인자 조립 비용은 그대로 남는다.

### 8.2 IL2CPP / AOT 제약

**IL2CPP(AOT 컴파일)를 기본으로 쓴다.** JIT 가 없으므로 런타임에 코드를 만들어내는 경로가 전부 막힌다.

- **리플렉션으로만 접근하는 타입·멤버는 코드 스트리핑에 날아간다.** 리플렉션 기반 직렬화·DI·플러그인 로더를 쓴다면 `link.xml` 에 보존을 선언한다.
- **런타임 코드 생성 불가** — `System.Reflection.Emit`, 동적 어셈블리, `dynamic`.
- **제네릭 가상 메서드의 값 타입 인스턴스화**는 AOT 에서 실패할 수 있다.
- **에디터(Mono/JIT)와 빌드(IL2CPP/AOT)는 다른 런타임이다.** 에디터에서 됐다고 빌드에서 되는 게 아니다 — 이 절의 항목들이 그 대표 유형이다.

> IL2CPP·스트리핑 레벨의 **설정 방법**은 빌드 스킬 소관이다. 여기에는 그 설정이 **코드 작성에 강제하는 것**만 적는다.

### 8.3 시크릿을 클라이언트에 두지 않는다

IL2CPP 는 IL 디컴파일 난이도를 올릴 뿐 **암호화가 아니다.**

- **문자열 상수는 바이너리에 평문으로 남는다.**
- 에셋 번들 · `Resources` 내용은 추출 가능하다.
- 네트워크 통신은 프록시로 그대로 보인다.

따라서 **API 키 · 서명 시크릿 · 결제 검증 로직을 클라이언트 코드나 에셋에 두지 않는다.** 가치가 걸린 검증(결제 · 재화 · 랭킹)은 서버가 단독으로 수행한다.

## §9. 에셋 로드 · 해제

- 런타임 에셋 로드는 **단일 로더를 경유**한다. 호출부마다 직접 로드하지 않는다.
- `Resources.Load` 는 신규 코드에서 쓰지 않는다 — 빌드에 전량 포함되어 초기 로딩·용량을 늘린다. Addressables 등 지연 로드 경로를 쓴다.
- **로드한 것은 반드시 해제한다.** Addressables 는 참조 카운트 방식이라 `Release`(핸들) / `ReleaseInstance`(인스턴스)를 빠뜨리면 메모리에서 내려가지 않는다. **로드 지점과 해제 지점의 짝을 맞춘다** (§4 생명주기 대칭과 같은 원칙).
- 해제 책임은 **로드한 쪽**이 진다. 화면·씬 단위로 로드했으면 그 단위가 닫힐 때 해제한다.
- 같은 에셋을 여러 곳에서 쓰면 **각자 로드하고 각자 해제**한다. 한쪽이 임의로 전체 해제하지 않는다.
- 구체 로더 API와 경로 규칙은 **L4(project-rules)** 소관이다.

## §10. 직렬화 · 프리팹

### 10.1 직렬화 필드

- 인스펙터 노출은 **`[SerializeField] private`** 를 기본으로 한다. `public` 으로 열어 노출시키지 않는다 — 인스펙터 노출과 접근 권한은 다른 문제다.
- **직렬화된 필드의 이름을 바꾸면 인스펙터·프리팹·에셋에 저장된 값이 조용히 사라진다.** 에러도 경고도 없다. 이름을 바꿔야 하면 **`[FormerlySerializedAs("이전이름")]`** 을 함께 단다.
- 같은 이유로 **타입 변경 · 클래스 이동(네임스페이스 변경 포함)** 도 값 소실을 일으킨다. 옮기기 전에 영향 범위를 확인한다 (`SKILL.md` Part B §4).
- Unity 직렬화는 **프로퍼티 · 딕셔너리 · 다형 필드 · null 을 저장하지 않는다.** 필요하면 직렬화 가능한 형태로 바꾸거나 `ISerializationCallbackReceiver` 를 쓴다.
- 중첩 깊이 제한이 있다. 깊은 트리는 ScriptableObject 참조로 끊는다.

### 10.2 프리팹

- **인스턴스 오버라이드가 프리팹 수정을 덮는다.** 프리팹을 고쳤는데 씬에서 반영이 안 되면 오버라이드를 먼저 의심한다.
- 공통 부분은 **프리팹 변형(Variant)** 으로 파생한다. 복사본을 만들어 각자 수정하면 이후 공통 변경이 전부 수작업이 된다.
- **프리팹 안에서 씬 오브젝트를 참조할 수 없다.** 필요하면 런타임에 주입한다(§11).

## §11. 씬 · 전역 상태

- **씬 간 직접 참조는 불가능하다.** 씬 A의 오브젝트를 씬 B에서 인스펙터로 물릴 수 없다. 런타임 주입이나 중개자를 쓴다.
- `DontDestroyOnLoad` 오브젝트는 **씬을 다시 로드해도 살아남는다.** 중복 생성 방지와 상태 초기화 경로를 함께 설계한다. 없으면 재시작할수록 인스턴스가 쌓인다.
- **`static` 필드는 씬 로드로 초기화되지 않는다.** 플레이 세션이 끝나도 값이 남아 다음 판에 새어든다. 정적 상태를 둘 거면 **명시적 리셋 경로**를 만든다.
- 에디터에서 도메인 리로드를 끄면(Enter Play Mode Options) 정적 상태가 더 오래 살아남는다. **에디터에서만 재현되거나, 에디터에서만 재현 안 되는** 버그의 흔한 원인이다.
- 씬 로드 완료 시점에 의존하는 초기화는 **콜백으로** 처리한다. 프레임 수를 세지 않는다.

## §12. 물리

- **물리 갱신은 `FixedUpdate`, 입력·표시는 `Update`.** 물리 계산을 `Update` 에 두면 프레임레이트에 따라 결과가 달라진다.
- **Rigidbody 를 `Transform` 으로 직접 움직이지 않는다.** `MovePosition` / `MoveRotation` / 힘 적용을 쓴다. Transform 직접 조작은 충돌 판정을 건너뛴다.
- `FixedUpdate` 안에서는 `Time.fixedDeltaTime` 을 쓴다.
- 콜라이더를 매 프레임 켜고 끄거나 크기를 바꾸면 물리 재계산 비용이 든다.
- **레이캐스트는 레이어 마스크를 명시한다.** 전체 레이어 대상 캐스트는 비싸고 의도치 않은 대상을 잡는다.
- 매 프레임 경로에서는 **비할당 API**(`RaycastNonAlloc` 계열)를 쓴다 (§6).

## §13. UI 성능

모바일 · WebGL 에서 UI 는 프레임 예산을 가장 쉽게 잡아먹는 곳이다.

- **자주 바뀌는 UI 와 정적인 UI 를 다른 Canvas 로 분리한다.** 한 Canvas 안의 요소가 하나만 바뀌어도 그 Canvas 전체가 다시 배칭된다.
- **Layout Group · Content Size Fitter 는 비싸다.** 정적 레이아웃이면 배치를 확정해 굽거나 직접 좌표를 준다.
- 클릭받지 않는 이미지 · 텍스트는 **`Raycast Target` 을 끈다.** 켜져 있으면 매 입력마다 후보로 검사된다.
- 짧게 숨겼다 보일 것은 `SetActive` 토글 대신 **`CanvasGroup` 의 `alpha` · `interactable`** 을 쓴다. 오래 숨길 것은 비활성화가 낫다.
- **매 프레임 텍스트를 갱신하지 않는다.** 값이 바뀔 때만 갱신한다 (§6).

## §14. 테스트

- **엔진에 의존하지 않는 로직은 EditMode 테스트로 덮는다.** 계산 · 상태 전이 · 데이터 변환이 대상이다.
- 엔진 생명주기가 필요한 것만 PlayMode 테스트로 간다. 느리므로 최소한으로.
- **테스트가 어려우면 대개 의존이 잘못 배치된 신호다.** 테스트용 우회로를 뚫기 전에 구조를 본다 (`SKILL.md` Part A 원칙 2).
- 되돌릴 수 없는 경로(결제 · 재화 소모 · 저장 덮어쓰기)는 **회귀 테스트를 반드시** 둔다.
