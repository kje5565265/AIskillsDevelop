# .NET 서버·툴 층 (L3)

Unity 밖의 .NET 프로젝트(웹 API / 백그라운드 서비스 / CLI 툴)에서만 성립하는 룰. Unity 프로젝트에는 적용하지 않는다.

---

## §1. 의존성 주입과 수명

| 수명 | 용도 | 주의 |
|---|---|---|
| `Singleton` | 상태 없는 서비스, 설정, 캐시 | **가변 상태를 두면 스레드 안전이 필요**하다 |
| `Scoped` | 요청 단위 컨텍스트, DB 세션 | Singleton 이 Scoped 를 주입받으면 안 된다 (captive dependency) |
| `Transient` | 가볍고 상태 있는 객체 | 생성 비용이 크면 부적합 |

- **구현이 아니라 인터페이스를 주입**받는다 (Part A 원칙 1).
- **서비스 로케이터 금지** — 생성자에서 컨테이너를 꺼내 쓰지 않는다. 의존이 시그니처에 드러나야 한다.
- 생성자에서 I/O 나 긴 작업을 하지 않는다. 초기화가 필요하면 명시적 `InitializeAsync`.

## §2. 계층 경계

```
API/Controller  →  Application/Service  →  Domain  →  Infrastructure
```

- **바깥 계층의 타입이 안쪽으로 새지 않는다.** HTTP 요청·응답 타입이 Domain 에 들어가면 안 된다.
- **DTO와 도메인 모델을 분리**한다. 외부 계약이 내부 모델 변경에 끌려다니면 안 된다.
- Infrastructure(DB / 외부 API / 파일)는 **인터페이스 뒤에** 둔다. 도메인 로직이 구체 기술을 알지 않게 한다.

## §3. 비동기 — L2 강화

- **끝까지 비동기.** `.Result` / `.Wait()` / `GetAwaiter().GetResult()` 를 요청 경로에서 쓰지 않는다.
- 라이브러리·인프라 코드는 `ConfigureAwait(false)`.
- **`CancellationToken` 을 받아 전달**한다. 요청 취소가 하위 I/O까지 전파돼야 한다.
- 백그라운드 작업을 `Task.Run` 으로 던져놓고 잊지 않는다. 실패가 조용히 사라진다.

## §4. 설정과 비밀

- 설정은 **강타입 옵션 객체**로 받는다. 문자열 키로 여기저기서 꺼내지 않는다.
- **비밀을 코드·저장소에 두지 않는다.** 환경변수·시크릿 저장소를 쓴다.
- 환경별 분기는 설정으로 한다. 코드에 `if (환경 == "prod")` 를 흩뿌리지 않는다.

## §5. 신뢰 경계

서버는 **클라이언트 입력을 신뢰하지 않는다.**

- 결제·재화·점수처럼 가치가 걸린 계산은 **서버가 단독으로** 수행하고 검증한다. 클라이언트가 보낸 결과값을 그대로 적용하지 않는다.
- 진입점에서 입력을 검증한다. 검증 위치를 한 곳으로 모아 우회 경로가 생기지 않게 한다.
- 인증(누구인가)과 인가(무엇을 할 수 있는가)를 분리한다.
- **외부에 나가는 에러 메시지에 내부 구조를 노출하지 않는다.** 스택 트레이스·쿼리·경로는 로그로만.

## §6. 로깅

- **구조화 로깅**을 쓴다 — 문자열을 미리 조립하지 말고 파라미터로 넘긴다.
- 로그 레벨을 구분한다. 정상 흐름을 `Error` 로 남기지 않는다.
- **개인정보·토큰·결제 정보를 로그에 남기지 않는다.**
- 요청 단위 상관 ID를 붙여 추적 가능하게 한다.

## §7. 데이터 접근

- 쿼리를 문자열로 조립하지 않는다 — 파라미터 바인딩.
- **N+1 쿼리를 만들지 않는다.** 루프 안에서 DB를 때리는 코드를 경계한다.
- 트랜잭션 경계를 명시한다. 여러 저장소에 걸친 변경은 경계를 먼저 정한다.
- 조회 전용 경로는 추적 없이 읽는다.

## §8. 테스트

- 도메인 로직은 인프라 없이 테스트 가능해야 한다 — 그게 §2 계층 분리의 실질적 목적이다.
- 테스트가 어려우면 대개 **의존이 잘못 배치된 신호**다. 테스트용 우회로를 뚫기 전에 구조를 본다.
- 결제·정산처럼 되돌릴 수 없는 경로는 **회귀 테스트를 반드시** 둔다.
