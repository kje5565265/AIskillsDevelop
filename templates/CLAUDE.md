## AI 스킬 사용 규칙

요청에 해당하는 스킬이 있으면 **작업을 시작하기 전에 반드시 로드한다.**

**스킬 본문은 `.claude/skills/` 와 `.agents/skills/` 에 동일하게 있다.** 도구마다 보는 곳이 다르고 **각자 자기 자리를 알아서 찾는다.** 경로를 지정하지 않는다. **두 경로의 내용이 다르면 배포 사고이므로 보고한다.**

| 건드리는 것 | 스킬 |
|---|---|
| 소스 · 데이터 파일 (`.cs` `.ts` `.cpp` · CSV/xlsx · 프리팹) | `code-convention` |
| `.md` 문서 — 작성 · 수정 · 이동 · 위치/파일명 결정 | `document-convention` |
| **작업을 기록한다** — `docs/work-log/` 편집 · *"작업 남겨줘"* · *"어디까지 했는지 남겨줘"* | `work-log` |
| 커밋 · 풀 · 푸시를 실행한다 | `git-procedure` |
| 하루의 **시작 · 마무리 루틴**을 돌린다 (*"아침루틴"* · *"마무리루틴"*) | `session-routine` |

**판단 기준은 작업의 무게가 아니다. 축이 셋이다** — **대상 파일** · **실행하는 명령** · **사용자 발화**. 주석 한 줄 · 로그 한 줄 · 오탈자 한 글자 같은 가벼운 수정도 전부 포함이며, 커밋 · 풀 · 푸시를 실행하면 파일 종류와 무관하게 `git-procedure` 도 포함한다. **"가벼우니 생략해도 되겠다"는 판단을 하지 않는다.** 스킬은 세션당 한 번만 읽으면 되므로 가벼운 작업에서 읽어도 비용이 늘지 않는다.

**여럿이 걸리면 전부 읽는다.**
(제외: 읽기 · 질문 · 조사만 하는 경우 · 대화만)

> **스킬 자동 로드는 어느 도구에서도 보장이 아니다.** 도구가 보장하는 것은 이 문서가 컨텍스트에 들어가는 것까지고, 여기 적힌 지시를 이행할지는 모델 판단이다. 그래서 아래 안전망을 이 문서에 직접 둔다.

## 안전망 — 스킬을 못 읽었을 때도 지킨다

**파일 읽기·쓰기 (Windows)**

- 셸로 파일을 읽거나 쓸 때는 UTF-8 을 명시한다. PowerShell 5.1 은 BOM 이 없으면 시스템 ANSI 로 처리해 한글이 깨진다.
- **읽은 내용이 깨져 보이면 그대로 판단하지 말고 다시 읽는다.** 쓰기가 더 위험하다 — 잘못 읽어서 잘못 쓰면 파일이 통째로 손상된다.
- 셸 없이 처리할 수 있으면 네이티브 파일 도구를 우선한다.

**깃**

- 작업을 완료해도 **자동 커밋 금지.** 사용자의 명시 지시까지 대기한다.
- **이력·작업을 지우는 조작 금지** — `push --force`(`--force-with-lease` 포함) · `reset --hard` · `checkout`/`restore` 로 되돌리기 · `clean -fd` · `stash` · **푸시된 커밋 amend.** 필요해 보이면 실행하지 말고 보고한다.
- **에셋은 AI 가 임의 머지 금지** — 충돌이든, 충돌 없이 양쪽이 같은 파일을 건드렸든 항상 사용자에게 넘긴다. LFS 바이너리(`.fbx` `.psd` `.png`) · `.meta`(GUID) · 프리팹/씬은 예외 없다 (확장자 대소문자 무관).
- `pull` 은 merge 방식(**rebase 금지**), `add` 는 경로 명시(**`git add -A` 금지**).

**코드 변경**

- **외과적 변경** — 요청에 직결되는 라인만 바꾼다. 인접 코드 정리 · 스타일 보정 · 자발적 리팩터 금지.
- **영향 분석** — 기존 시스템을 바꾸기 전에 참조 전수 검색 + 상태 Add/Remove 생명주기 확인.
- **주석 불신** — 주석이 아니라 함수 본문과 호출부를 따라가 판단한다.
- **테스트 로그 블록 삭제 전 범위 보고** — `AITESTLOG_<컨텐츠명>-BEGIN`/`-END` 로 감싼 구간을 지울 때는 **범위를 먼저 보고한다.** `END` 없는 `BEGIN` 과 중첩은 **삭제하지 않고 보고한다** — 범위 계산이 틀리면 정상 코드가 함께 지워진다.

## 코드 컨벤션

**저장소의 소스·데이터 파일을 편집하기 전에 `code-convention` 스킬을 로드한다.** 설계 원칙(책임 경계 · 다형성 · 인터페이스 분리)과 변경 안전 절차의 단일 진실원이다.

- 스킬은 §0 절차로 이 저장소의 **언어 · 프레임워크 · 플랫폼 층을 판정해** 해당 레퍼런스까지 함께 읽는다. 판정을 건너뛰고 원칙만 적용하지 않는다.
- **새로 정해진 코드 룰은 이 문서가 아니라 `code-convention/references/project-rules.md` 에 추가한다.** 여기에 쌓으면 매 세션 상주하면서 정작 코딩하는 순간엔 attention 이 흐려진다.

## 문서 규칙

**저장소의 `.md` 문서를 작성·수정하기 전에 `document-convention` 스킬을 로드한다.** 문서 위치 · 명명 · 링크 규칙과 개발 이력 · 계획 문서 형식의 단일 진실원이다.

- 오탈자 한 글자도 포함이다. 문서를 옮기거나 이름을 바꾸는 것, 위치·파일명을 정하는 것도 대상이다.
- 개발 이력은 `docs/develop-history/`, 계획은 `docs/plan/` 에 남긴다. 상세 형식은 스킬에 있다.

## 작업 기록

**`docs/work-log/` 를 건드리거나 *"작업 남겨줘"* 라고 하면 `work-log` 스킬을 로드한다.** 줄 형식 · 갱신 · 보류 해소 순서 · 아카이브 규칙의 단일 진실원이다.

- **작업을 그때그때 한 줄로 남기고, 아직 처리하지 않은 보류를 한곳에 모은다.** 아침루틴이 읽고 마무리루틴이 갱신한다.
- **`docs/work-log/work-log.md` 는 파일을 통째로 다시 쓰지 않는다.** 필요한 줄만 고친다. 열린 보류의 현황은 **이 파일에만 있어 복구 경로가 없다.**
- **셸로 쓰지 않는다.** 네이티브 파일 도구만 쓴다 — 통째로 깨지지 않고 일부 줄만 깨진 채 자라서 눈에 안 띈다.

## 깃 절차

**`git commit` · `git pull` · `git push` 중 하나라도 실행하면 `git-procedure` 스킬을 로드한다.** 커밋 메시지 작성 · 검증, 머지 충돌 처리, 커밋→페치→풀→푸시 절차의 단일 진실원이다.

- 사용자의 명시적 커밋·푸시 지시가 곧 절차 시작 확인이다. 이미 지시받았으면 다시 되묻지 않는다.
- 커밋 메시지는 AI 가 작성하고, 저장소 밖 UTF-8 메시지 파일 + `git commit -F <파일>` 경로로 전달한다.
- 보고는 깃 용어 대신 평문으로 한다. 단, 명령 실패 원문은 사용자가 전달할 수 있도록 붙인다.

## 세션 루틴

**하루의 시작과 마무리를 돌릴 때 `session-routine` 스킬을 로드한다.** *"아침루틴 하자"* · *"마무리루틴 하자"* 처럼 **사용자가 그렇게 말했을 때만** 발동하며, 각 단계의 순서와 멈춤 조건, 완료 정의의 단일 진실원이다.

- **아침** — 받아올 것이 내 작업과 겹치는지 보고, 받고, 무엇이 바뀌었는지 알리고, **작업 로그와 개발 이력 최신 1건**을 읽어 브리핑한다.
- **마무리** — 컴파일을 확인하고, 심어둔 테스트 로그를 걷어내고, 작업물을 올린 뒤 **개발 이력과 작업 로그**를 쓰고 다시 올린다.
- **애매하면 실행 전에 묻는다.** 어느 루틴인지, 어디까지 하라는 것인지 모호하면 추측하지 않고 선택지를 낸다.

## 애매하거나 겹칠 때

- **어느 스킬인지 애매하면 「어겼을 때 무엇이 망가지나」로 판정한다** — 코드가 잘못되면 `code-convention`, 문서가 어긋나면 `document-convention`, 이력이 망가지면 `git-procedure`. 스킬이 늘어나도 같은 기준으로 판정한다.
- 같은 내용이 두 스킬에 있으면 **한쪽이 원본이고 다른 쪽은 포인터다.** 충돌하면 원본을 따르고, **중복 자체를 보고한다.**
