# 개발 계획 (plan)

**개발을 시작하기 전에** 무엇을 어떤 순서로 할지 쓰는 곳이다.

| | |
|---|---|
| **파일명** | `YYYY-MM-DD-<slug>.md` |
| **인용 키** | `PLAN:<slug>` |
| **언제** | 개발 **시작 전** |

계획과 그 결과 이력은 **같은 slug 을 공유한다** — `PLAN:character-dash` 로 계획하고 `DH:character-dash` 로 남기면 짝이 한눈에 보인다.

## 형식

**실행 계획**은 각 단계에 검증을 붙인다.

```
1. [작업] → 검증: [확인 명령/기준]
```

검증이 붙는 형식이라 **검증 없는 완료 주장**이 구조적으로 막힌다. 비싼 검증(패키징 빌드·풀 플레이 테스트)은 마지막에 통합한다.

**절차를 지시하지 않는 문서는 자유 서술이다** — 리뷰 · 브리핑 · 회고 · 설계 설명 · 사양서.

## 질문 우선

- 사용자가 명시하지 않은 가정이 계획에 **1건 이상** 들어가면 질문으로 분리한다. 0건이면 면제
- 1줄 수정 · 오타 · 로그 추가 같은 **자명한 작업은 질문 면제**
- **답을 알면서 승인만 받으려는 안전빵 질문은 하지 않는다**

## 규칙의 단일 진실원

형식 · 명명 · 링크 규칙은 **`document-convention` 스킬**이 정한다.
