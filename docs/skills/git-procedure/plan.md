# `git-procedure` 설계

**커밋 · 풀 · 푸시 안전 절차**의 단일 진실원. 이름이 브랜치 전략(git-flow)으로 오해되지 않도록 `description` 첫 문장에 범위를 박는다.

> ## 절 번호 대조 — 이 문서와 `SKILL.md` 는 번호가 다르다 ★ (2026-08-25)
>
> 구현하면서 `SKILL.md` 에 절이 **두 개 늘었고**(§1.1 멈춤은 두 종류다 · §4.4 무엇을 문서로 남기는가), 그 뒤가 전부 하나씩 밀렸다.
>
> | 이 문서 | `SKILL.md` |
> |---|---|
> | 1.1 잔여 변경 | **§1.2** |
> | 1.2 push 거부 | **§1.3** |
> | 1.3 브랜치명 | **§1 본문 항목** (절이 사라짐) |
> | 1.5 보고는 평문 | **§5** (독립 절로 승격) |
> | 2.1.1 인계 | **§2.2** |
> | 2.2 조용한 머지 | **§2.3** |
> | 4.4 머지 커밋 | **§4.5** |
> | — | **§1.5 받기 전용** (2026-08-25 신설) |
> | — | **§4.6 문서만 올리는 커밋** (2026-08-25 신설) |
>
> **재번호하지 않는다.** 이 문서의 절 번호를 다른 문서와 개발 이력이 가리킨다. 절이 사라져도 뒤 번호를 당기지 않고, 새 절은 뒤에 붙인다.
>
> **대신 인용할 때 어느 문서인지 반드시 밝힌다** — `SKILL.md §2.3` · `plan §2.2`. 번호만 쓰면 4회차에 났던 사고가 반복된다 (`§2.3` 을 `§2.2` 로 거꾸로 정정한 일).
>
> **에이전트가 런타임에 읽는 것은 `SKILL.md` 다.** 실제 동작을 말할 때는 그쪽 번호가 기준이다.

> ## 이 스킬이 존재하는 이유 — 결과를 검증할 수 없는 사람을 대신한다 ★
>
> **2026-08-25 정정** — 원래는 *"쓰는 사람이 프로그래머가 아니다"* 였다. **프로그래머도 쓴다**(사용자 확인). 기획·디자인은 **극단 사례**이지 대상 전부가 아니었다.
>
> **그래도 설계는 안 바뀐다. 비대칭이기 때문이다.**
>
> | | 결과 |
> |---|---|
> | 프로그래머 기준으로 짜면 | **기획·디자인 쪽에서 사고가 난다** |
> | 낮은 쪽에 맞추면 | 프로그래머는 **같은 절차를 더 잘 쓸 뿐** 잃는 것이 없다 |
>
> 그리고 **AI 는 지금 누가 타이핑하는지 판정할 수 없다.** 판정하려 들면 세션마다 답이 갈린다.
>
> 그래서 전제는 **「결과를 스스로 검증할 수 없는 사람을 대신해 깃을 만진다」** 로 남는다. 이것이 설계 전반을 지배한다.
>
> - **인계는 「깃 클라이언트를 여세요」로 끝나면 안 된다.** 직접 해결할 수 있는 사람에겐 그것도 답이지만, 그럴 수 없는 사람에게는 막다른 길이다. **양쪽 다 이어갈 수 있는 형태로** 낸다 (§2.1)
> - **보고 문구에 깃 용어를 쓰지 않는다.** `untracked` · `non-fast-forward` 는 전달되지 않는다. **상대가 프로그래머로 보여도 예외를 두지 않는다** (§1.5)
> - **커밋 메시지는 AI 가 전부 쓴다.** §4 규약이 하는 일이 줄지 않고 늘어난다
> - **비가역 조작 금지가 더 무겁다.** 프로그래머는 사고를 알아채기라도 하는데 **이 사용자는 일어난 줄도 모른다** (§5)
> - 반대로 **"Unity 에서 열어 확인하세요"는 적절하다.** 그건 그분들이 매일 하는 일이다 (§2.2)

## 0. 발동 기준 — 「크기」가 아니라 「실행하는 명령」

다른 두 스킬(`code-convention` · `document-convention`)은 **파일**로 발동하는데 이 스킬은 **행위**로 발동한다. 그래서 진입점 라우팅의 *"어떤 파일을 건드리는가"* 축이 이 스킬을 덮지 못하고, *"파일 안 건드리니 해당 없음"* 오독이 성립한다.

> **`git commit` · `git pull` · `git push` 중 하나라도 실행하면 이 절차를 탄다.** 한 글자 수정의 커밋도 같다.
>
> **"이번엔 가벼우니 짧게 가겠다"는 판단을 하지 않는다. 그 판단 자체가 이 절차의 실패 지점이다.**
>
> 스킬은 세션당 한 번만 로드된다. 가벼운 작업에서 읽어도 총비용이 늘지 않는다.

**확인은 절차 시작 전 1회다.** 사용자의 명시적 커밋·푸시 지시가 **곧 그 확인**이므로 되묻지 않는다. 지시가 없는데 절차가 필요해 보일 때만 *"커밋할까요?"* 를 묻는다.

## 1. 절차

```
⓪ 현재 셸 확인 — 어느 셸로 진행하는지 한 줄로 밝힌다
① git add <경로 명시> + git commit -F <메시지 파일>
② git log -1 --format=%B          ← 메시지 저장 검증 (§3)
③ git fetch
④ git pull --no-rebase --no-edit  ← 충돌 시 §2 로 중단
⑤ 머지된 에셋 보고 (§2.2)
⑥ git push
```

- **커밋이 먼저인 이유** — 내 작업을 먼저 봉인해야 pull 이 실패해도 잃는 것이 없다
- `git add -A` **금지.** 변경 파일을 경로로 명시한다
- **`--no-rebase`** — `pull.rebase=true` 가 사용자 홈 `.gitconfig` 에 있으면 rebase 로 돈다. 안전망이 금지한 동작을 **설정이 대신 일으킨다**
- `git branch --show-current` 로 확인하고 **그 브랜치로만** 푸시한다

**멈춤은 두 종류다.**

| 종류 | 조건 |
|---|---|
| **게이트 멈춤** | 충돌 발생(§2) · 커밋 메시지 검증 실패(§3) |
| **명령 실패 멈춤** | git 명령이 0 이 아닌 코드로 끝나면 **언제나.** 인증 실패 · 원격 거부 · 업스트림 없음 · LFS 실패 · 훅 거부 |

**둘 다 확인이 아니라 보고하고 대기**다. 다음 단계를 시도해 우회하지 않는다.

### 1.1 잔여 변경

`add -A` 금지의 필연적 결과로 **① 이후에도 커밋 안 된 변경이 남는다.** Unity 에서는 상시 상태다(`.csproj` 재생성 · 에디터가 건드리는 `ProjectSettings` · 임포트로 갱신되는 `.meta`). 그 상태로 ④ 를 돌리면 겹치는 파일이 있을 때 *"Your local changes would be overwritten"* 로 실패한다.

- ① 뒤에 `git status` 로 잔여 변경을 확인하고 있으면 **목록을 보고한다**
- **`git stash` 는 사용자 지시가 있을 때만.** 잔여 변경을 통째로 치우는 비가역 조작이라 안전망에 금지로 들어가 있다

### 1.2 push 가 거부되면

③~⑥ 사이에 남이 푸시하면 non-fast-forward 로 거부된다. **흔한 일이고 사고가 아니다.**

> **③ → ④ → ⑤ → ⑥ 을 한 번 더 돈다.** 이미 승인된 절차의 재시도이므로 **확인을 다시 받지 않는다.**

안 적으면 두 갈래로 갈린다 — 되묻고 멈추거나(마찰), **`--force` 를 집거나**(안전망 위반).

### 1.3 브랜치명·remote 이름은 어디에도 적지 않는다 — 물어본다

실측상 전부 다르다 — AI_Develop `main` · Project_A `branch_DEV` · Origin `master`/`develop`. **그렇다고 다른 파일에 적어두지도 않는다.** 브랜치는 바뀌고 remote 는 추가되는데 적어둔 값은 안 따라간다 — **stale 값이 하나 생길 뿐**이다.

```bash
git branch --show-current          # 브랜치
git remote                         # remote 이름
```

**런타임에 물어보면 항상 맞다.** 그 브랜치로만 푸시하고, 다른 브랜치로 밀지 않는다.

### 1.4 LFS push 는 「명령 실패」로 오판되기 쉽다

Unity + LFS 첫 push 는 수 분이 걸리는데 에이전트 셸 기본 타임아웃은 대개 2분이다. **타임아웃은 0 이 아닌 종료 코드로 보여 "push 실패"로 보고된다.**

- ⑥ 은 **긴 타임아웃 또는 백그라운드**로 돌린다
- 불명확하게 끝나면 **`git fetch` 후 원격 상태를 다시 보고** 판정한다. 오판하면 다음 세션 브리핑이 거짓이 된다


### 1.5 보고는 평문으로 — 깃 용어를 쓰지 않는다 ★

**이 절차의 모든 사용자 대면 문구에 적용된다.** 읽는 사람이 깃을 모른다는 전제(문서 상단)에서 나온다.

| 쓰지 않는다 | 대신 |
|---|---|
| `untracked 파일이 3개 있습니다` | *"아직 저장(커밋)하지 않은 변경이 3건 있습니다"* |
| `non-fast-forward 로 거부됨` | *"제가 작업하는 사이 다른 분이 먼저 올리셨습니다. 받아서 합친 뒤 다시 올리겠습니다"* |
| `merge commit 이 생성됨` | *"양쪽 작업을 합쳤습니다"* |
| `LFS 전송 타임아웃` | *"용량이 큰 파일이라 업로드가 오래 걸립니다"* |
| `.meta GUID 충돌` | *"파일 연결 정보가 어긋났습니다"* |

- **커밋 해시·브랜치명·명령어를 보고 본문에 넣지 않는다.** 사용자가 그걸로 할 수 있는 일이 없다
- **파일은 전체 경로 대신 이름과 종류로** — `Assets/Prefabs/Player.prefab` → *"Player 프리팹"*
- **다음에 무엇이 필요한지 한 줄로 끝맺는다.** 상태만 알리고 끝내면 사용자가 무엇을 해야 할지 모른다

> **예외 — 에러 원문은 그대로 붙인다.** 명령 실패 멈춤(§1) 때는 평문 설명 뒤에 원문을 덧붙인다. 사용자가 프로그래머에게 전달할 수 있어야 한다.

## 2. 에셋 — 충돌은 개발자가, 조용한 머지는 보고한다

### 2.1 충돌 시 중단

**AI 는 에셋 충돌을 해결하지 않는다.** 머지 도구가 성공했든 실패했든, 드라이버가 있든 없든 마찬가지다.

| 종류 | 예 | 처리 |
|---|---|---|
| **코드·텍스트** | `.cs` `.ts` `.md` `.json`(일반) | AI 가 해결 |
| **컴파일 경계** | `.asmdef` `.asmref` | AI 해결 가능. 해결 후 **reference · define constraints · 플랫폼 include/exclude 확인** |
| **Unity YAML** | `.prefab` `.unity` `.asset` `.anim` `.controller` `.mat` `.spriteatlasv2` 등 | **사용자** |
| **전역·의존성** | `ProjectSettings/**` · `Packages/**` | **사용자** |
| **LFS 바이너리 · `.meta`** | `.fbx` `.psd` `.png` `.wav` / **모든 `.meta`** | **사용자** |

**판정은 `.gitattributes` 를 우선하되 좁히는 데 쓰지 않는다.**

```bash
git check-attr merge filter -- <경로>     # 파일을 눈으로 읽지 않는다
```

`merge=unityyamlmerge` 면 Unity YAML, `filter=lfs` 면 LFS 바이너리다. **선언에 없어도 위 표에 있으면 에셋으로 본다** — 새 Unity 버전이 새 확장자를 만들면 선언이 뒤처지는데, 그때 **덜 보수적으로 판정되면 안 된다.** 확장자 매칭은 **대소문자를 무시한다.**

> **`.gitattributes` 를 손으로 읽으면 틀린다** — `[attr]` 매크로 전개 · 후행 규칙 우선 · 하위 디렉터리 파일 · `core.ignorecase` 를 전부 놓친다. 실제로 이 플랜이 *"Project_A 의 `.Png` 2,123개가 선언과 어긋난다"* 고 적었다가 **오판으로 판명**됐다 — `core.ignorecase=true` 라 `check-attr` 은 정상적으로 `filter: lfs` 를 반환한다.
>
> **대소문자를 무시하는 근거는 그래서 바뀐다** — 어긋나서가 아니라, **`core.ignorecase` 가 로컬 설정이라 같은 저장소가 개발자 Windows 와 CI 리눅스에서 다르게 분류되기 때문**이다.

### 2.1.1 인계 — 「판단하지 않는다」와 「실행하지 않는다」는 다르다 ★

**AI 는 어느 쪽을 살릴지 정하지 않는다. 그러나 사용자가 정하면 그 지시를 실행한다.** 둘을 붙여놓으면 인계가 *"깃 클라이언트를 여세요"* 로 끝나는데, **그럴 수 있는 사람이면 애초에 AI 에게 깃을 안 시킨다.**

```
같은 파일을 두 분이 함께 수정하셔서 자동으로 합칠 수 없습니다.

- Assets/Prefabs/Player.prefab   (프리팹)
- Assets/Art/Boss.fbx            (3D 모델 파일)

각 파일을 어떻게 할지 알려주세요.
  ① 제 작업을 살린다        ② 상대 작업을 살린다
  ③ 둘 다 살려야 한다 / 판단이 어렵다  → 직접 확인이 필요합니다

말씀해주시면 그대로 처리하고 푸시까지 이어서 진행하겠습니다.
```

- **①·② 를 사용자가 고르면 AI 가 실행한다.** 선택은 사용자 판단이므로 원칙이 유지되고, **실행은 AI 가 하니 인계가 실제로 끝난다**
- **③ 이면 멈춘다.** 둘 다 필요한 병합은 파일을 열어봐야 하고, 그건 AI 가 할 일이 아니다
- **파일 종류를 평문으로 덧붙인다** — `LFS 바이너리` 가 아니라 `3D 모델 파일`, `GUID` 가 아니라 `연결 정보`
- 사용자가 직접 해결하고 **"해결됐어" 라고 하면 확인 없이 ⑤ 부터 이어간다**

> **AI 가 스스로 `--ours` / `--theirs` 를 고르지 않는다는 원칙은 그대로다.** 바뀐 것은 **사용자가 고른 뒤에도 AI 가 손을 떼고 있었다는 점**이다.

### 2.2 조용한 머지는 막지 않고 보고한다 ★

**충돌로 잡히면 이미 안전하다** — git 이 멈추고 사람이 본다. 실제 사고는 반대쪽에서 난다.

```
양쪽이 같은 .prefab 을 서로 다른 줄에서 수정
  → 충돌로 안 잡히고 조용히 합쳐짐
  → fileID 참조가 어긋나 있는데 아무도 모름
```

> **실측 (2026-08-24, Project_A)** — `.gitattributes` 는 25개 확장자에 `merge=unityyamlmerge` 를 선언하는데 `git config` 어느 층에도 드라이버(`merge.unityyamlmerge.cmd`)가 **없다.** 선언만 있고 드라이버가 없으면 git 은 **기본 텍스트 머지로 조용히 떨어진다.** `.meta` 8,178개가 지금 줄 단위 머지 대상이다.

**이걸 pull 전에 막으려 하지 않는다.** ⑤ 에서 **머지 결과를 보고**한다.

```bash
git -c core.quotepath=false diff --name-only ORIG_HEAD HEAD
```

이 목록에 §2.1 의 에셋이 있으면 한 줄 덧붙인다.

```
※ pull 로 아래 에셋이 자동 머지됐습니다. Unity 에서 열어 확인하시길 권합니다.
   - Assets/Prefabs/Enemy.prefab
```

- **명령 하나이고 `ORIG_HEAD` 는 pull/merge 가 자동으로 세운다.** 업스트림 판정도 교집합 계산도 필요 없다
- 사고를 100% 막지는 못하지만 **모르고 지나가는 것은 막는다.** 드라이버 미설치 상태에서는 이것만으로도 현 상태보다 확실히 낫다

> **폐기한 설계** — 한때 *"pull 전에 양쪽이 건드린 파일의 교집합을 구해 에셋이 있으면 멈춘다"* 를 넣었다가 뺐다. 이유는 §7 결정 이력 12.

## 3. 커밋 메시지 전달 — 셸 함정

| 셸 | 여러 줄 문자열 문법 |
|---|---|
| Bash (Git Bash) | heredoc — `git commit -F - <<'EOF'` … `EOF` |
| PowerShell | here-string — `git commit -m @'` … `'@` (닫는 `'@` 는 **0 컬럼**) |

**Bash 에서 PowerShell here-string 을 쓰면** 리터럴로 넘어가 첫 줄이 `@` 가 되고, git 이 빈 줄 전까지를 제목으로 합쳐 **`@ 의도한제목`** 으로 오염된다. **에러 없이 커밋이 성공해 알아채기 어렵다.** 개인 프로젝트에서 2회 발생(`26199c600` · `2836ca5e4`).

**두 번째 함정** — PS 5.1 은 네이티브 exe 인수를 시스템 ANSI 로 인코딩한다. `git commit -m @'한글'@` 은 문법이 맞아도 cp949 로 도착하고, git 은 UTF-8 을 가정해 저장한다 → **깨진 메시지가 올라간다.**

### 3.1 그래서 셸 분기를 없앤다

**위 표는 배경 지식으로만 남기고 실제 지시는 하나로 고정한다.**

```
1. 메시지를 UTF-8(BOM 없음) 파일로 쓴다   ← 네이티브 파일 도구 사용
2. git commit -F <파일>
3. git -c core.quotepath=false log -1 --format=%B  로 검증
4. 메시지 파일을 지운다
```

- **`@` 오염과 인코딩 사고가 동시에 닫힌다.** 셸 문자열 문법을 아예 안 쓴다
- **메시지 파일은 저장소 밖 임시 경로에 쓴다.** 워킹트리에 쓰면 §1.1 의 잔여 변경 보고에 섞인다
- **② 검증은 `-m` 단일 행이어도 실행한다.** 오염 여부를 사전에 판단하지 않는다 — 사고 2회가 전부 *"괜찮을 줄 알았던"* 경우다
- 제목이 `@` 로 시작하거나 한글이 깨졌으면 즉시 amend. **이미 푸시됐으면 고치지 말고 보고한다**

> **PowerShell 로 검증 출력을 읽을 때 주의** — PS 5.1 은 git 출력을 콘솔 코드페이지로 디코딩한다. 인코딩 설정이 맞지 않으면 **멀쩡한 커밋이 깨져 보여 정상 커밋을 amend 하게 된다.** 검증이 미심쩍으면 Git Bash 에서 다시 본다.

## 4. 커밋 메시지 규약

### 4.1 커밋 직전 5줄 체크리스트

1. **제목** = `{대상} {결과형 동사}` 한 줄, **한글 40자 이내**. 절차 카운트·추상 표현·작업 메타 금지
2. **본문** = 점 목록 기본. 배경 산문 단락 금지
3. **파일·필드·줄 수 나열 금지** — diff 에 이미 있다
4. **약식 기호 금지** — `→` `↔` `vs` 는 자연어로
5. **자가 검증** — 맥락 없는 팀원 / 2주 뒤 본인이 추적 가능한가 · **이 세션에서만 통하는 용어·영어가 남아 있지 않은가**

**언어는 한국어.** 컬럼은 제목 80 · 본문 100(한글은 2컬럼이므로 제목 = 한글 40자).

### 4.2 외부 독자 친화 룰

AI 가 쓰는 커밋 메시지는 **세션 컨텍스트를 그대로 토해내는 경향**이 있다.

| # | 룰 | 요지 |
|---|---|---|
| 1 | **제목은 결과 중심 한 줄** | `{대상} {결과형 동사}`. **「대상」은 기능·시스템 이름이지 파일명이 아니다**(룰 5).<br>O `보스 텔레그래프 가드 미발동 이슈 수정` / X `보스 BT 정확도 보강 (3 cycles)` |
| 2 | **본문은 점 목록** | **금지** — 배경 산문 단락(PR·이슈 트래커 영역).<br>**허용** — 점 목록만으로 본문 전체를 채워도 된다. 한 줄 안에 행위+인과가 녹는 표현은 권장 |
| 3 | **세션 로컬 약어 금지** | 임시 지칭(`dp-1`)·절차 약어(`sub-X`)는 풀어쓴다. 문서를 지칭하면 실제 파일명 |
| 4 | **풀리는 영어는 한국어로** | `bullet` → 점 목록, `revert` → 되돌리기. 고유명사·API·표준 약어는 유지 |
| 5 | **파일·필드·줄 수 나열 금지** | 본문은 **"무엇을 했다"**(행위 + 의미)만.<br>O `LockOn 컴포넌트가 회전 변경 뒤 내부 기준값을 동기화하도록 보정`<br>X `LockOnComponent.cs 의 CachedYaw 수정, PlayerController.cs 12줄 변경` |
| 6 | **표현 자연성** | 약식 기호 금지 · 점 목록은 주제별로 묶어 배치.<br>X `(settings.json, Kanban 사양 2건)` — 괄호로 디테일 packing 금지<br>**적용 범위는 커밋 메시지 본문에 한정. 문서는 `document-convention` 소관** |
| 7 | **사소한 부수 변경 제외** | 로그 제거·주석 정리·들여쓰기는 본문에 줄을 추가하지 않는다. **단 그것이 작업 의도 자체면 포함** |
| 8 | **자가 검증 3항목** | 2주 뒤 추적 가능한가 · 맥락 없는 팀원이 이해 가능한가 · 본인만 아는 용어가 없는가 |

### 4.3 완성 예시

**단순 커밋** — 제목 + 평평한 점 목록. 번호 섹션을 쓰지 않는다.

```text
공격자 리코일 좌우 교대 구현

- 연속 패리·가드당함 시 좌우 리코일 방향을 번갈아 적용
- 마지막 적용 방향을 기억해 다음 피격에서 반대 방향 선택
```

**다주제 커밋** — 주제별 번호 그룹핑 허용. **번호 하위 점 목록에도 룰 5 가 그대로 적용된다.**

```text
적 기상 흐름 안정화 및 사양서 갱신

1. 기상 중 피격 처리
   - 기상 모션 진행 중 피격되면 다운으로 되돌리지 않고 경직만 적용
   - 무적 구간이 기상 종료까지 이어지도록 정리
2. 사양서
   - 기상 상태 전이 규칙을 현재 구현에 맞게 정정
```

WIP 중간 저장처럼 임시 성격이 강한 커밋은 **제목만** 허용한다.

### 4.4 머지 커밋에는 적용하지 않는다

④ pull 이 만드는 `Merge branch 'x' of ...` 는 위 룰을 전부 위반한다.

> **머지 커밋의 기본 메시지는 그대로 둔다.** §4 는 **내가 작성하는 커밋**에만 적용되고 **② 검증도 머지 커밋에는 하지 않는다.**

## 5. always-on 안전망

**원문은 이 문서에 두지 않는다.** 원본은 진입점(`CLAUDE.md` · `AGENTS.md` — 바이트 동일 미러)의 **「먼저 지킬 것」 절**이다. 복제하면 그 순간부터 drift 다.

| 룰 | 막는 위험 | 복구 |
|---|---|---|
| 자동 커밋 | 지시 없이 커밋 | `reset` 로 되돌림 |
| **비가역 조작** | force push · `reset --hard` · `checkout`/`restore` 되돌리기 · `clean -fd` · `stash` · 푸시된 커밋 amend | **불가** |
| **에셋 임의 머지** | 충돌 시 AI 가 해결 | 조용히 깨진 참조 — 어렵다 |
| 명령 형태 | rebase pull · `git add -A` | 되돌림 가능 |

**「비가역 조작」이 이 스킬의 핵심 기여다.** 초안 4줄에는 없었고 amend 금지만 §3 안에 있었는데 — **정확히 스킬이 안 떴을 때 사라지는 위치**다. ⑥ push 가 거부되면 가장 자연스러운 다음 수가 `--force` 다.

**always-on 에는 로드 의무와 파국 방지 룰만 올린다.** 절차·판정표·메시지 규약을 올리지 않는다.

`AGENTS.md` 에 들어갈 Codex 용 한 줄 — *"Codex 는 슬래시 커맨드를 직접 실행하지 않으므로, 커밋 작업 신호 시 해당 `SKILL.md` 를 문서로 읽고 그 규칙을 적용한다."* 진입점이 미러라 양쪽에 들어가며, Claude 쪽에는 무해한 잉여다.

## 6. 훅

`UserPromptSubmit` 훅으로 커밋·푸시 신호를 감지해 스킬 로드를 주입한다. **Claude Code 전용 보강**이며 3종 공통 안전망은 §5 가 담당한다.

```powershell
# UTF-8 로 stdin 을 직접 연다 — 콘솔 코드페이지를 건드리지 않는다
$reader = New-Object System.IO.StreamReader(
    [Console]::OpenStandardInput(), (New-Object System.Text.UTF8Encoding($false)))
$raw = $reader.ReadToEnd()
if ($raw -match '깃|\bgit|커밋|푸시|올려줘|commit|push|pull') {
    '{"hookSpecificOutput":{"hookEventName":"UserPromptSubmit","additionalContext":"Load the git-procedure skill before staging or committing."}}'
}
```

- **`[Console]::InputEncoding` 을 세우지 않는다** — 콘솔 핸들이 없으면 예외로 죽고(조용히), 성공해도 `SetConsoleCP` 는 **사용자 터미널의 코드페이지를 전역으로 바꾼다**
- **`.ps1` 은 UTF-8 with BOM 으로 저장한다.** PS 5.1 은 BOM 없는 스크립트를 ANSI 로 파싱해 **정규식 안의 한글이 파싱 시점에 깨진다.** 저장소 규칙(BOM 없음)의 **의도적 예외**이므로 이유를 파일 첫 줄 주석에 남긴다 — 안 적으면 다음 사람이 규칙 위반으로 보고 지운다
- 입력 JSON 을 파싱하지 않는다. 키워드 포함 여부만 보므로 파서가 필요 없고, **파서가 있으면 파서가 깨진다**
- 호출은 `powershell.exe -NoProfile -File ...` 로 명시한다. `shell: "powershell"` 옵션은 5.1 이 아니라 **pwsh(7)** 를 쓴다
### 6.1 트리거는 `깃` · `git` 을 통째로 잡는다 ★

**조합을 하나씩 나열하는 방식은 반드시 샌다.** 초안은 `커밋|푸시|올려줘|깃에 올리|…` 였는데 **사용자가 실제로 쓰는 「깃작업」·「git작업」을 네 형태 모두 못 잡았다**(실측).

| 입력 | 초안 | 현재 |
|---|---|---|
| `깃작업 좀 해줘` · `깃 작업 해줘` | **X** | O |
| `git작업 해줘` · `git 작업 부탁해` | **X** | O |
| `일딴 여기까지 작업된거 깃 마무리해줘` | **X** | O |
| `풀어서 설명해줘` · `스풀러 오류가 나` · `디지털 사이니지` | X | X |

**오탐과 미탐의 비용이 다르다.** 이것이 넓게 잡는 근거다.

| | 일어나는 일 | 비용 |
|---|---|---|
| **오탐** | 스킬 로드 한 번 | **거의 0.** 세션당 1회이고 어차피 나중에 쓸 수도 있다 |
| **미탐** | **스킬 없이 깃을 만진다** | 안전망만 남는다 — 사고 구간 |

- **`\bgit`** — 앞에만 경계를 둔다. `디지털` · `legitimate` 속의 `git` 을 피하면서 `github` · `gitignore` · `git작업` 은 잡는다
- **`깃`** 은 경계 없이 둔다. `깃발` · `깃털` 이 걸리지만 개발 대화에서 나올 일이 없고 걸려도 손해가 없다
- **한글 `풀` 은 넣지 않는다** — `풀어서` · `스풀러` 는 **매 프롬프트마다** 걸리는 종류라 성격이 다르다

> **사용 룰이 정해져 있다** — 사용자는 깃 작업을 시킬 때 **「깃작업」 · 「git작업해줘」** 형태로 말한다. 훅은 그것보다 넓게 잡되, **그 두 형태는 반드시 걸려야 한다.**

**테스트에 한글 프롬프트 케이스를 반드시 넣는다.** 「오탐·과탐」만 보면 한글 실패를 통과시킨다 — ASCII 키워드로는 잘 동작하기 때문이다.

| 4 | `git-flow` → **`git-procedure`** 개명 | 브랜치 전략으로 오해된다 |
| 5 | 훅 구현 **PowerShell**, Python 기각 | Python 미설치 시 **조용히 실패** |
| 6 | 브랜치명·remote 이름을 **공용 층에서 제외** | 실측상 전부 다르다 |
| 7 | 분류는 **`.gitattributes` 우선, 단 좁히지 않음** | 손 유지 표는 이미 어긋나 있었다(`.spriteatlasv2` 누락). 선언이 낡으면 **더 보수적으로만** 판정되게 |
| 8 | `.gitattributes` 조회는 **`git check-attr`** | 손으로 읽어 `.Png` 근거를 틀렸다 — 매크로 전개·`core.ignorecase` 를 놓쳤다 |
| 9 | 데이터 자산은 **경로 기준**, 크기 임계 없음 | "대형"의 임계값은 정하면 계속 논쟁거리가 되고 판정하려면 파일을 열어야 한다 |
| 10 | 커밋 메시지는 **`-F` 단일 경로** | `@` 오염과 PS 인코딩이 동시에 닫힌다. 셸 분기 자체가 사라진다 |

### 12번을 폐기한 이유 ★

*"pull 전에 양쪽이 건드린 파일의 교집합을 구해 에셋이 있으면 멈춘다"* 를 넣었다가 뺐다. **막으려던 위험(조용한 머지)은 실재하지만 비용이 이득을 넘었다.**

교차 검증 5회에서 나온 지적 22건 중 **15건 안팎이 이 한 기능에서 파생**됐다.

| 게이트가 만든 문제 | |
|---|---|
| `merge-base` · 두 `diff` · 교집합 계산 | PowerShell 이 `@{u}` 를 **해시테이블로 파싱해 파스 에러** (실측 확인) |
| `check-attr --stdin` | PowerShell 이 `<` 를 **예약 연산자로 거부** (실측 확인) |
| 파이프로 넘긴 한글 경로 | **BOM + CR 이 붙어 `unspecified` 반환** → 에셋이 코드로 오분류 (실측 확인) |
| rename 처리 | `-M` 이 **rename × 편집 교차에서 탐지를 좁힌다** (실측 확인) |
| 과발동 | `ProjectSettings` 류가 발동 대부분을 차지하는데 위험도는 가장 낮다 |
| 알림 등급 신설 | **always-on 이 금지한 일을 스킬이 허용**하게 되어 3층 배치가 뒤집혔다 |

**교집합을 셸에서 계산하려는 순간 이식성·인코딩 문제가 통째로 딸려온다.** 그리고 복잡한 절차는 **에이전트가 실전에서 건너뛸 이유**가 된다 — 검토에서 실제로 그렇게 답했다.

**대신 §2.2 로 낮췄다** — pull 후 `ORIG_HEAD` 비교 한 줄로 **막는 대신 알린다.** 사고를 100% 막지는 못하지만 **모르고 지나가는 것은 막고**, 위 여섯 문제가 전부 사라진다.

> **되살리지 말 것.** 다음 세션이 *"조용한 머지를 막아야 하지 않나"* 라고 생각하면 이 절을 먼저 읽는다.
>
> **지적 원문은 남아 있지 않다** — [`./review.md`](./review.md) 는 2026-09-09 에 비웠다(`skill-pipeline` §6.1, 크기 상한 60KB 초과). **위 표가 그 판정의 요약이고, 이것으로 충분하다고 판단했다.** 왕복 과정을 되살릴 이유가 생기면 깃 이력에서 꺼낸다.

## 8. 파일 구조

```
git-procedure/
└─ SKILL.md      ← 전부. 레퍼런스 없음. 전 프로젝트 바이트 동일
```

**`document-convention` 과 같은 단일 파일 구조다.** 셋을 비교하면 층이 필요한 조건이 드러난다.

| 스킬 | 층 | 왜 |
|---|---|---|
| `code-convention` | 5층 + `project-rules.md` | 코드가 **언어·프레임워크·플랫폼·프로젝트마다 실제로 다르다** |
| `document-convention` | 단일 | 문서 규칙은 **조직 공통** |
| **`git-procedure`** | **단일** | **깃 동작은 어디서나 같다** |

**`project-rules.md` 를 두지 않는다.** 한때 브랜치명·remote·LFS 운영을 거기 넣으려 했으나 **넷 다 런타임 조회로 끝난다**(§1.3 · §2.1). 그리고 그 파일은 **프로젝트 개발자가 자기 룰을 넣는 공간**이지 우리가 채울 슬롯이 아니다 — 우리가 *"거기에 브랜치명을 둔다"* 고 설계하는 것 자체가 남의 공간에 대한 월권이다.

**더 쪼개지도 않는다.** 커밋 메시지 규약은 절차와 **항상 같이 쓰이고**(커밋하는 순간 둘 다 필요하다), 에셋 표는 파일로 뺄 분량이 아니다. 엔진별로 나누면 *"어느 표를 읽을지"* 판정하는 단계가 새로 생긴다.

## 9. `description` 초안

**대상 + 트리거 키워드를 첫 문장에**, 역할 설명은 맨 뒤(잘려도 무해).

```
"깃작업"·"git작업"·"커밋"·"푸시"·"올려줘" 언급 또는 commit·push·pull 수행 시 로드한다.
커밋 메시지 작성·검토, 머지 충돌 처리도 대상. 브랜치 전략이 아니라 커밋→푸시 절차와
메시지 규약의 단일 진실원.
```

약 130자. 목표(250자) 안이다.

- **`"깃작업"`·`"git작업"` 을 맨 앞에 둔다.** 사용자가 정한 사용 룰이 이 형태이고, **훅이 없는 Codex·Cursor 는 `description` 매칭으로만 뜬다** — 여기 없으면 3종 중 둘이 안 뜬다
- **"브랜치 전략이 아니라"는 맨 뒤에.** 이름 오해를 막되 잘려도 트리거는 살아야 한다
