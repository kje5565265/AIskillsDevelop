# 개발 이력 (develop-history)

**개발이 끝난 뒤** 무엇을 했고 왜 그렇게 했는지를 남기는 곳이다.

| | |
|---|---|
| **파일명** | `YYYY-MM-DD-<slug>.md` |
| **인용 키** | `DH:<slug>` |
| **언제** | 개발 **완료 후** |

**작업 하나 = 문서 하나.** 기존 문서에 누적하지 않고 **매번 새로 만든다.**

## 무엇을 적나

- **한 일** — 행위와 의미. 파일·줄 수는 적지 않는다 (diff 에 있다)
- **판단과 근거** — 버린 대안과 그 이유까지
- **검증** — 확인한 것만. 확인 못 한 것은 아래 보류로
- **보류** — "나중에 하자"를 **왜 미뤘는지 + 어떤 조건이면 재개하는지**와 함께. 여기 안 적히면 증발한다
- **제외한 것** — 기획에 있지만 이번에 뺀 항목과 사유

## 규칙의 단일 진실원

형식 · 명명 · 링크 규칙은 **`document-convention` 스킬**이 정한다.

`.agents/skills/document-convention/SKILL.md` 를 읽는다. 없으면 `.claude/skills/document-convention/SKILL.md`.

> **2026-09-21 이전의 개발 이력은 이 저장소에 없다.** 배포 대상 프로젝트의 내부 사정이 섞여 있어 옮기지 않았다. `docs/skills/*/plan.md` 에 링크 없이 남은 `DH:` 인용 키는 그 시기의 기록을 가리키며, 판단 근거는 plan 의 결정 이력에 이미 흡수돼 있다.

> 이 파일은 **빈 폴더가 git 에 올라가지 않기 때문에** 폴더를 남기는 역할도 한다. 지우지 말 것.
