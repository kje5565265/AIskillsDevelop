# iOS 층 (L3.5)

Unity + iOS 타깃에서만 성립하는 룰.

> **프로비저닝 · 인증서 · 아카이브 · 업로드는 빌드 스킬 소관이다.** 여기에는 **코드 작성에 영향을 주는 것**만 적는다.
>
> ⚠️ 이 층의 여러 항목은 어기면 **앱스토어 심사에서 리젝된다.** 빌드가 성공해도 출시가 막히는 유형이라 코드를 쓰는 시점에 지켜야 한다.

---

## §1. 조건부 컴파일

- iOS 전용 코드는 `#if UNITY_IOS` 로 감싼다.
- 네이티브 플러그인 호출은 `[DllImport("__Internal")]` 이며 **다른 플랫폼에서는 링크가 깨진다.** 반드시 감싼다.

## §2. 권한 문자열 — 없으면 크래시하거나 리젝된다

- 카메라 · 사진 · 마이크 · 위치 · 추적 등 권한이 필요한 API 를 호출하려면 **Info.plist 에 사용 목적 문자열이 반드시 있어야 한다.** 없으면 **호출 즉시 크래시**하고, 있어도 문구가 부실하면 리젝된다.
- **권한 API 를 새로 쓰기 시작하면 그 사실을 빌드 담당에게 알린다** — Info.plist 항목 추가가 필요하다. 코드만 넣고 끝내지 않는다.

## §3. ATT (App Tracking Transparency)

- 광고 식별자(IDFA)를 쓰는 SDK 를 초기화하기 **전에** ATT 권한을 요청한다. 순서가 뒤바뀌면 식별자를 못 받아 광고 수익이 떨어진다.
- ATT 요청 팝업은 앱이 **포그라운드 활성 상태**일 때만 뜬다. 스플래시·로딩 중에 호출하면 무시된다.
- **거절이 기본이라고 가정**하고 흐름을 만든다.

## §4. 저장 · iCloud 백업

- **`Application.persistentDataPath` 는 기본적으로 iCloud 백업 대상**이다. 재다운로드 가능한 캐시 · 에셋을 여기 두면 **"불필요한 데이터 백업"으로 리젝**된다.
- 캐시성 데이터는 **백업 제외 플래그**를 설정하거나 `Application.temporaryCachePath` 를 쓴다.
- 세이브 데이터는 백업 대상으로 두는 게 맞다. **둘을 구분해서 배치한다.**

## §5. 결제 · 외부 링크

- 디지털 재화 구매는 **인앱 결제만** 허용된다. 외부 결제 페이지로 유도하는 **링크 · 버튼 · 문구를 코드나 UI 에 넣지 않는다.**
- 외부 브라우저를 여는 링크는 목적이 명확해야 한다.

## §6. 화면

- **Safe Area 를 반영한다** (`Screen.safeArea`). 노치 · Dynamic Island · 홈 인디케이터 영역에서 UI 가 잘린다.
- **홈 인디케이터 영역에 조작 UI 를 두지 않는다** — 시스템 스와이프와 충돌한다.

## §7. 생명주기 · 메모리

- 저장은 **`OnApplicationPause(true)`** 에서 한다. iOS 는 백그라운드 프로세스를 예고 없이 종료한다.
- 백그라운드 실행 시간이 제한적이다. 복귀 시 재연결 · 재검증 경로를 만든다.
- **메모리 압박 시 OS 가 경고 없이 앱을 종료한다.** 대용량 텍스처 · 오디오를 상주시키지 않는다 (`framework-unity.md` §9 해제 규칙과 함께 적용).
