# 프로젝트 고유 룰 (L4) — 템플릿

> **이 파일은 프로젝트마다 다르다.** 공용 배포본에는 이 템플릿이 들어가고, 각 프로젝트가 자기 내용으로 채운다.
> 다른 층(`SKILL.md`, `lang-*.md`, `framework-*.md`)은 전 프로젝트 동일하므로 **여기 말고 저기를 고치지 않는다.**

L4는 우선순위가 가장 높다. 여기 적힌 룰은 L1~L3를 override 한다. 단 `SKILL.md` Part B(변경 안전 절차)만은 override할 수 없다.

---

## §1. 무엇을 여기 쓰는가

| 쓴다 | 쓰지 않는다 |
|---|---|
| 이 프로젝트에만 있는 API·클래스를 **어떻게 써야 하는가** | 일반적인 C# 문법 규칙 → `lang-csharp.md` |
| 이 프로젝트에서 **금지된 표준 API와 그 대체재** | 일반적인 Unity 규칙 → `framework-unity.md` |
| 데이터 파이프라인의 **동기화 의무** | 설계 원칙 → `SKILL.md` |
| 이 프로젝트의 **네이밍 예외** | 아키텍처 일반론 |
| 플랫폼 제약이 코드에 강제하는 것 | |

**판정 질문**: *"이 문장에서 프로젝트 고유명사를 빼면 말이 되는가?"*
- 된다 → 상위 층으로 올린다
- 안 된다 → 여기가 맞다

## §3. 데이터 파이프라인

> 데이터의 단일 진실원이 무엇이고, 어느 방향으로 흐르며, **무엇을 같이 갱신해야 하는지.**
> 파이프라인 중간 산출물만 고쳐서 다음 빌드에 날아가는 사고가 가장 흔하다.

- **단일 진실원**: _(예: `Table/balance_*.xlsx`)_
- **흐름**: _(예: xlsx → exporter → CSV → 런타임 접근 API)_
- **동시 갱신 의무**: _(예: CSV만 고치면 다음 Export가 xlsx 기준으로 덮어써 변경이 사라진다. 즉시 테스트용으로 CSV를 먼저 손대더라도 같은 세션 안에서 xlsx를 반드시 맞춘다.)_

## §6. 플랫폼 제약이 코드에 강제하는 것

> 출시 플랫폼의 제약 중 **구현을 바꾸는 것들.** 기획 문서가 아니라 여기 적는 이유는, 코드를 쓰는 순간 판단에 들어가야 하기 때문.

| 제약 | 코드에 미치는 영향 |
|---|---|
| _(예시)_ 첫 화면 로딩 10초 이내 | 초기 로드 에셋 최소화, 큰 리소스는 지연 로드 |
| _(예시)_ 통신은 `wss://` 만 | 평문 소켓 사용 금지 |
| _(예시)_ 특정 네이티브 플러그인 미지원 | 해당 의존성 신규 추가 금지 |
