# WebGL 층 (L3.5)

Unity + WebGL 타깃에서만 성립하는 룰. **브라우저 샌드박스 안에서 도는 단일 스레드 환경**이라, 데스크톱·모바일 빌드에서 멀쩡하던 코드가 그대로 깨지는 지점이 많다.

> **빌드 압축 방식 · 호스팅 · 배포는 빌드 스킬 소관이다.** 여기에는 **코드 작성에 영향을 주는 것**만 적는다.

---

## §1. 스레드가 없다

- **`System.Threading` · `Thread` · `Task.Run` 을 쓸 수 없다.** 컴파일은 통과하고 런타임에 실패한다.
- 비동기가 필요하면 **코루틴** 또는 `UnityWebRequest` 조합을 쓴다.
- `lock` · `Monitor` 는 의미가 없다. **동시성 전제를 코드에서 제거한다.**
- 무거운 계산은 **프레임에 나눠** 처리한다. 메인 스레드를 막으면 브라우저 탭 전체가 멈춘다.

## §2. 동기 파일 IO 가 없다

- **`System.IO.File` 로 직접 읽고 쓸 수 없다.** `Application.persistentDataPath` 는 브라우저 IndexedDB 에 매핑된다.
- 저장 후 **flush 를 명시적으로 호출**해야 실제로 반영된다. 빠뜨리면 탭을 닫을 때 사라진다.
- **`streamingAssetsPath` 는 URL 이다.** `UnityWebRequest` 로 읽는다.

## §3. 네트워크

- **브라우저 CORS 정책을 따른다.** 서버가 허용 헤더를 주지 않으면 요청이 막힌다. *에디터에서 되던 요청이 브라우저에서만 실패하는* 대표 원인이다.
- **`System.Net.Sockets` 사용 불가.** 소켓 통신은 WebSocket 으로만 가능하다.
- HTTPS 페이지에서는 **`ws://` 가 차단된다.** `wss://` 를 쓴다.

## §4. 로딩 · 용량

- **초기 빌드에 들어가는 것이 곧 첫 화면 로딩 시간**이다. 큰 리소스는 빌드에서 분리해 지연 로드한다.
- 첫 화면에 필요 없는 씬 · 에셋을 초기 로드에 넣지 않는다.
- 텍스처 · 오디오 압축을 **웹 기준**으로 잡는다. 모바일 네이티브 기준을 그대로 쓰면 용량이 커진다.

## §5. 브라우저 정책 — 사용자 제스처 안에서만 되는 것들

- **사운드는 사용자 입력 이후에만 재생된다.** 자동 재생은 차단된다. 첫 터치·클릭에서 오디오를 깨우는 경로가 필요하다.
- **전체화면 · 클립보드 · `Application.OpenURL`** 은 사용자 제스처 안에서만 동작한다. 비동기 콜백 안에서 부르면 팝업 차단에 걸린다.
- **탭이 백그라운드로 가면 프레임 루프가 느려지거나 멈춘다.** 시간 경과를 프레임 수로 계산하지 않는다 (`framework-unity.md` §6).

## §6. 예외 · 로그

- 빌드 옵션에서 예외 지원을 끄면 **`try/catch` 가 동작하지 않는다.** 예외에 의존한 흐름 제어를 쓰지 않는다.
- 브라우저 콘솔이 유일한 로그 출구다. 출시 빌드에 로그가 남지 않게 정리한다 (`framework-unity.md` §8.1).
