# Android 층 (L3.5)

Unity + Android 타깃에서만 성립하는 룰.

> **빌드 설정 · 서명 · 스토어 업로드는 빌드 스킬 소관이다.** 여기에는 **코드 작성에 영향을 주는 것**만 적는다.

---

## §1. 조건부 컴파일

- Android 전용 코드는 `#if UNITY_ANDROID` 로 감싼다.
- 네이티브 호출부는 **반드시** 감싼다. 감싸지 않으면 다른 플랫폼 빌드가 링크 단계에서 깨진다.
- 에디터에서 플랫폼이 Android 로 설정돼 있으면 `UNITY_EDITOR` 와 `UNITY_ANDROID` 가 **동시에 켜진다.** 에디터에서만 다르게 동작해야 하면 `UNITY_EDITOR` 를 먼저 분기한다.

## §2. 파일 · 저장소

- 쓰기 가능한 경로는 **`Application.persistentDataPath`** 다. 외부 저장소 경로를 문자열로 조립하지 않는다 — 권한 정책이 OS 버전마다 바뀐다.
- **`Application.streamingAssetsPath` 는 APK 안의 압축 경로**라 `System.IO.File` 로 직접 읽을 수 없다. `UnityWebRequest` 로 읽는다.
- **파일 경로가 대소문자를 구분한다.** 에디터(Windows)에서 되던 경로가 기기에서만 깨지는 대표 원인이다.

## §3. 뒤로가기 — 처리하지 않으면 앱이 종료된다

하드웨어·제스처 뒤로가기는 Unity 에서 **`KeyCode.Escape`** 로 들어온다. **아무도 처리하지 않으면 앱이 그대로 종료된다.**

- 뒤로가기는 **한 곳에서 중앙 관리**한다. 화면마다 각자 `Escape` 를 보면 여러 화면이 동시에 반응한다.
- 팝업 · 모달이 열려 있으면 그것부터 닫는다 — 스택 개념이 필요하다.
- 최상위에서 종료할 때는 확인을 받는다.

## §4. 권한

- 런타임 권한은 **필요한 직전에** 요청한다. 부팅 시 일괄 요청하면 거절률이 오른다.
- **거절당한 경우의 대체 흐름을 반드시 만든다.** 권한이 항상 허용된다고 가정하지 않는다.
- 사용할 때마다 **현재 상태를 확인**한다. 사용자가 설정에서 언제든 회수할 수 있다.

## §5. 네이티브 상호작용 (JNI)

- **`AndroidJavaObject` / `AndroidJavaClass` 는 `IDisposable` 이다.** `using` 으로 받거나 명시적으로 `Dispose` 한다. 빠뜨리면 JNI 로컬 참조가 누수된다.
- 네이티브 호출은 **메인 스레드**에서 한다. 다른 스레드에서 필요하면 `AndroidJNI.AttachCurrentThread`.
- **콜백이 네이티브 스레드로 들어올 수 있다.** 그 스레드에서 Unity API 를 호출하지 않는다 — 메인 스레드로 마샬링한다.

## §6. 화면 · 입력

- **Safe Area 를 반영한다** (`Screen.safeArea`). 펀치홀 · 제스처 바 영역에서 UI 가 잘린다.
- 해상도 · 종횡비가 기기마다 크게 다르다. 고정 좌표 대신 앵커 기반 레이아웃.
- 회전 · 멀티윈도우로 **해상도가 런타임에 바뀔 수 있다.** 레이아웃 계산값을 캐시했다면 갱신 경로가 필요하다.

## §7. 생명주기

- 홈 버튼 · 전화 수신으로 **`OnApplicationPause(true)`** 가 온다. **저장은 여기서** 한다 — `OnApplicationQuit` 은 호출되지 않을 수 있다.
- 백그라운드에서 프로세스가 예고 없이 종료될 수 있다. 복귀 시 상태 복원 경로를 만든다.
